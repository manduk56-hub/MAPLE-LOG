# 시스템 공통 백업

`boss-notes`는 보스 일기의 날짜별 메모이며 데이터 버전 1의 `{ notes: [{ date, text }] }`를 공통 저장 API로 관리한다. 날짜는 유효한 `1900-01-01`~`9999-12-31` 형식이고 중복되지 않으며, 메모는 2,000자 이하이고 최대 20,000개다. 보스 기록 없이 저장할 수 있으며 보스 일기를 삭제해도 유지된다. 빈 메모를 저장하면 해당 날짜의 메모만 제거한다. 손상된 데이터·지원하지 않는 버전은 덮어쓰지 않으며, 메모가 없는 이전 백업을 복원할 때 기존 메모를 유지한다.

`expense-diary`는 소비·수익 일기이며 데이터 버전 4의 `{ entries: [{ id, date, character, category, items: [{ name, price, balance? }], memo }], notes: [{ date, text }] }`를 저장한다. 기존 소비의 양수 `price`는 그대로 유지하며, 수익은 음수 `price`로 저장한다. UI는 반대로 소비를 `-`, 수익을 `+`로 표시한다. 직접 입력 항목은 `balance`가 없고, 잔액 계산 항목은 `balance: { start, end }`와 `price = start - end`를 저장한다. 잔액은 0 이상의 안전한 정수이고, `price`는 부호가 있는 안전한 정수다. 잔액이 증가하면 수익이며 차이와 가격이 불일치하는 데이터는 거부한다. `아이템 판매`·`도박` 분류를 지원한다. 합계는 BigInt로 계산하며 소비 순위는 지출 항목만 합산한다. 메모는 일기를 삭제해도 유지된다.

버전 1의 단일 항목 `{ name, amount }`는 읽을 때 `items: [{ name, price: amount }]`로 변환하고, 기존 `장비 구매`는 `아이템 구매`로 표시한다. 버전 2·3의 양수 소비와 메모는 그대로 읽는다. 기존 버전 데이터는 당시 허용한 양수 가격과 분류로 검증하며, 읽기만으로 저장소를 변경하지 않는다. 일기나 메모 저장 시 버전 4로 저장한다. 버전 1·2·3·4 복원 데이터는 해당 버전 형식으로 검증한다. 지원하지 않는 미래 버전이나 손상된 데이터는 덮어쓰지 않는다. 보스 전용 백업 복원 시 이 일기는 유지된다.
새 백업은 버전 3이며 `systems` 안에 시스템별 `{ version, data }`를 담는다. `boss-diary`는 기존 보스 일기다. 이전 버전 1·2 백업도 복원할 수 있다.

복원은 파일에 포함된 시스템만 교체한다. 파일에 없는 시스템은 유지하며, 아직 구현되지 않은 시스템도 원본 데이터와 버전을 그대로 저장하고 다시 내보낸다. 기존 보스 일기 저장 키 `maplelog.records.v1`과 사용자 기록 폴더는 유지한다.

새 메뉴 구현 시 개별 localStorage 키 대신 공통 API를 사용한다:

```js
const saved = window.MapleSystems.get('new-system'); // null 또는 { version, data }
window.MapleSystems.set('new-system', { entries: [] }, 1);
```

시스템 ID는 영문 소문자로 시작하는 영문 소문자·숫자·하이픈, 최대 64자이며 이후 이름을 바꾸지 않는다. 데이터는 JSON으로 표현할 수 있어야 한다. 시스템 자체의 형식을 변경하면 데이터 버전을 올리고, 읽을 때 이전 데이터의 변환과 검증을 구현한다. 지원하지 않는 미래 버전은 덮어쓰지 않고 보존한다. 기존 `boss-diary`는 보스 일기의 저장 함수를 사용한다.

복원 완료 후 앱을 새로고침하여 모든 시스템이 복원된 데이터를 읽는다. 이 백업 컨테이너는 데이터를 함께 이동시키는 구조이며, 메뉴 사이의 수익 합산 같은 기능은 해당 메뉴 구현 시 연결한다.
