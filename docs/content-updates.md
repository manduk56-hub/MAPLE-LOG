# 새 버전 배포와 기존 기록 유지

보스 목록은 이 프로젝트에서 수정한 뒤 실행 폴더 ZIP이나 설치 파일로 배포합니다. 온라인 확인이나 콘텐츠 다운로드는 하지 않습니다.

## 목록 수정과 배포

1. content/catalog.json의 bosses에 보스와 난이도를 추가합니다. items는 아이템 자동완성 목록이며 자유 입력도 가능합니다.
2. 변경 날짜와 목록 버전을 정리합니다. 목록 버전은 안내용이며 설치 파일에 포함된 목록을 항상 사용합니다. 이전 온라인 목록 캐시가 새 설치 목록을 덮어쓰지 않습니다.
3. npm run content:build로 content.js를 생성합니다. 개발 실행과 설치 파일 빌드 때도 자동 생성됩니다.
4. npm run check와 node --test tests/*.test.cjs로 확인하고 앱 버전을 올려 npm run build로 새 설치 파일을 만듭니다.
5. ZIP 배포는 `scripts/package-portable.ps1 -OutputPath 원하는경로\메이플로그.zip`으로 포장합니다. 사용자에게 앱을 종료한 뒤 기존 실행 폴더에 압축을 풀어 파일 전체를 덮어쓰도록 안내합니다. 설치 파일을 배포하는 경우에는 앱을 종료하고 기존 프로그램 위에 설치하도록 안내합니다. 두 방식 모두 개인 기록은 배포 파일에 포함하지 않습니다.

## 기록 보존 원칙

프로그램 파일은 설치 폴더에, 기록은 Windows 사용자별 %APPDATA%/Maplelog에 저장됩니다. 버전이나 설치 폴더가 달라져도 같은 Windows 계정에서는 기존 기록을 읽습니다. NSIS 설치 설정은 사용자 데이터 삭제를 비활성화합니다.

후속 버전에서도 다음 값을 유지해야 합니다.

- Electron 사용자 데이터 폴더: %APPDATA%/Maplelog
- 앱 식별자: com.maplelog.diary
- 기록 페이지 주소: maplelog://app/
- 기록 저장 키: maplelog.records.v1

기록 형식 변경이 필요한 경우 기존 형식 읽기와 변환을 함께 지원해야 합니다. 기존 보스 이름이 새 목록에서 빠지더라도 이전 기록은 유지되며 수정 시 해당 기록에만 기존 이름 선택지를 제공합니다. 새 기록은 목록에서만 선택합니다. 과거 아이템 이름과 당시 가격도 목록 변경으로 수정하지 않습니다.

다른 PC나 Windows 계정으로 이동할 때는 백업 다운로드로 JSON 파일을 보관하고 새 환경에서 백업 복원으로 가져옵니다. 웹 브라우저의 기록과 설치 앱의 기록은 별도이므로 웹에서 설치 앱으로 이동할 때도 같은 방법을 사용합니다.

## 실제 버전 교체 검증

node tests/upgrade-smoke.cjs 이전앱.asar 새앱.asar

별도의 임시 Windows 앱 데이터 폴더에서 이전 빌드를 실행해 테스트 일기를 저장한 다음, 다른 설치 경로의 새 빌드를 실행합니다. 원래 저장 내용, 로드된 기록, 예전 수량 형식의 총액, 목록에 없는 보스 이름이 유지되는지 확인합니다. 사용자 실제 기록은 열거나 변경하지 않습니다.
